# Maple Cash Overlay v1 — local-only Windows source integration
User verbatim: ok now implement all of it using everything we know, into my own overlay. simple.

Base: Javipen/maple-exp-overlay at 1a25186943a42fccd89eec2e0777c7b41ea5a21f, MIT (upstream LICENSE retained in the installed folder; derived from beanguri). Uses its existing passive screen capture, game-font EXP and wallet recognition, message deduplication, pickup OCR and click-through HUD; existing local-only network guard stays. No modification to FM Rush or other trackers. Separate LocalAppData folder MapleCashOverlayV1, no migration from other installed apps. No uploads to MCWO or Minerva. Hotkeys disabled initially to avoid clashes; use Start/Pause and Reset in main window. Existing HUD is simplified, repot row off by default.

New cash overlay extension shows observed raw pickup mesos/hr, raw plus known NPC-value/hr, observed pickups total and separate confirmed wallet change. Not actual realized net profit. Rate only after 60 active seconds, blank until pickup messages seen. Unknown price counts logged; * indicates unpriced units. No guess from closed inventory or FM valuation; known NPC prices from previous source research; item names matched exactly case-insensitively. Prepaid supplies not subtracted in gross display; wallet changes do not prove cash-only profit. CSV per-segment cumulative snapshots every 30s and before resets/map changes/close. Do not sum cumulative rows; use final row per segment. Captures with hidden map, pause, town or delayed pickup batch excluded. Map transitions are OCR-dependent; events near transition can be missed/misattributed. Partial/missed OCR possible; observed counts not guaranteed full pickup income. No false accuracy claim. Base full GUI and local log also available. Optional rank_maps.py reads saved MCWO JSON archive (not production backend); cap and contributor caveats unchanged.

Installer downloads immutable upstream source, retains LICENSE and assets, installs dependencies in own venv, patches three HUD captions only with exact anchor checks, compiles files, runs 5 isolated cash-core regression tests before launching; creates Desktop shortcut. It does not test live game OCR or upstream GUI. Requires Windows Python 3 and internet for setup; Tesseract installed separately for map names and unknown item OCR if absent. Local only after setup. No executable bundled. Installer not executed here. No all-99-engine merge: separate architectures and unknown licenses not copied. Minerva/msxp algorithms not ported; video OCR, automated vendor transaction detection and independent cash-specific public server ranking remain future work. No full video processing in v1. Source references in research/tracker-source-collection-2026-11-28. No tests claimed executed on Windows. No history deleted. Not full verbatim conversation archive.

## v1.2 — spawn research capture and offline scene analyzer
User verbatim: i also want you to track where monsters spawn, where other players are, and how quick monsters spawn, and how much exp, and monsters in relation to players
1-second lossless full client screenshots in foreground, with JSON sidecars containing UTC and monotonic capture timestamps, geometry, latest OCR context and its age, map uncertainty, EXP candidates/confidence/estimated flag, level, job, wallet age/read, party, item quantities, observed message EXP total, potion estimate and farming state. Latest context is asynchronous; not exact frame OCR. Existing CSV and prior screenshots preserved. 3,600 screenshots/hour maximum; 5 GiB free guard remains. No video or auto input.
scene_analysis.py is an offline working template matcher, labels monster/self/player/anchor crops when supplied, outputs per-frame pixel positions, observed counts, nearest detected player distance, and optional landmark-relative coordinates. No bundled live-calibrated templates; detection is not validated on actual game frames. Need real samples to build templates; unknown players or monsters may be missed, including animation variations. No exact respawn measurement implemented; gap_bounds helper computes time uncertainty for annotated disappearance/reappearance samples, not automatic association. Camera movement, offscreen monsters, occlusion and other players' kills prevent interpreting appearances as confirmed births or assigning EXP to a specific monster. Public sources https://maplestory.quest/maps and https://osmsdataexplorer.com/ provide reference spawn placements and monster stats; Minerva ADR 0008 documents its data model and modeled tick 7.56s; data not bundled or live-verified (direct JSON open failed). No automatic camera alignment beyond optional single matched landmark. Installer includes 5 new tests, not executed here. Windows/live OCR and detection unverified. No prior historical files removed.
