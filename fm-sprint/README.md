- **Hold F9** after the alert (or when entering the FM portal) until the channel change begins. Keep F9 unbound in the game. Open the channel menu normally. F9 is a held user request, not a stored future action. Pointer parking during the confirmed initial blackout is retained; when a verified channel menu appears, the scanner repositions to the fixed destination cell and dispatches at most one selection click and one confirmation click per uninterrupted hold. Menu header is rechecked before each; target selected-cell and confirm-button evidence required for confirmation. Release F9 to stop further clicks. If a click was not registered, release and hold F9 again while the menu remains open. No blind click-spam or new automatic shop opening in default mode. If focus or geometry changes, release and re-hold or unlock to reset; if Windows refuses pointer movement, click manually. F12 stops the current run; Shift+2 unlocks. The F9 path is specific to native 1366×768; the route map also works for other sufficiently large clients. Do not map F9 to a repeating macro; a single held key is sufficient. The older optional -Navigate behavior remains available but is not needed for F9.

# FM Sprint — two-engine prototype

**Separate project, not a production FM Rush update.** Built on pinned Step 13 commit `a80a9ffbcc2a4a1616b5cfdc8c91b35c430df8fb` and the existing HeneFM browser bridge. Close existing FM Rush (the same localhost port is used). Extract the ZIP, launch either BAT for pointer assist. For experimental automatic channel selection/confirmation and ONE estimated shop-sign click, run `powershell -NoProfile -ExecutionPolicy Bypass -File .\START_FM_SPRINT.ps1 -Engine runescape -Navigate` (or `maplestory`). These actions are not guaranteed to be authorized by Nexon; automated gameplay can risk account penalties. No anti-cheat bypass, network injection or game-memory access. Live buying is NOT implemented. No installed Windows launch has been tested by ChatGPT. The setup may require Git authentication and a working Python environment.

## Common route
- Assigned start: CH20 (the repository default; optional `-StartChannel 17` if desired), standing on row 3 at the base of the central rope between FM14 and FM15. The application cannot independently prove the starting channel or avatar position. A same-channel skip assumes that assigned start is correct.
- Existing live feed auto-lock and map overlay, no HeneFM refresh added. F8 repeats the route instruction; bind a single F8 keystroke in G HUB if desired. Walking, teleporting and opening the channel menu remain player-controlled. Route guidance uses the existing 20-room `route_logic.py`. The old V5 FM1 movement macro is a documented but unqualified candidate, not installed automatically. No fabricated timing for 19 other rooms.
- On observed entrance-to-black transition, park the cursor on the intended channel cell. Manual room arrival without a sampled blackout also parks it. Only a native 1366x768 game client enables the new lifecycle actions. Unsupported size keeps ordinary overlay behavior.
- With experimental `-Navigate`, actual channel-menu header correlation must be >=0.95, then select target cell once. Confirm button and target-cell blue state must both be observed before one confirm click. Header is rechecked immediately before each click. On observed second blackout, project first-frame shop pin and park cursor there. First positive FM-room title triggers one optional estimated shop click, not a rapid uncontrolled spam loop. Projection is NOT verified seller identity; camera and spawn may still move, and the client channel ID is not independently verified. If the one click misses, use the existing red shop guide manually.
- On shop detection, park pointer away from fixed inventory band. Existing item overlay stays click-through. F12 aborts this run, Shift+2 unlocks. F12 stays latched when the window moves or the target metadata changes; inventory evidence must be fresh, match the current lock, and not identify a sold row. Focus or geometry mismatch suppresses actions. No purchases, no automated selection of a row or quantities, no confirmation of receipts. Blank stats are not a trustworthy statless classification.

## Recognition engines
- **RuneScape:** original native exact bitmap/name-shape plus sprite foreground fingerprint bank, learned only from the existing OCR read. Reuses an observed fingerprint, otherwise uses compact OCR. Conflicting identities permanently abstain until evicted. Does not use the OBS-tuned tolerant Step 13 coordinates in the native client. Advisory name matches only; upstream scroll and price logic unchanged.
- **MapleStory:** existing Step 11 compact six-name-band WinRT OCR and target-independent exact raw-pixel cache, with original strict scroll branch and price validation. Both versions inherit exact gate / geometry fallback, sold and hover checks, duplicate-name protection, and current overlay behavior. The new RuneCache uses actual native signatures, not an imported RuneScape bot. Neither is a new independently qualified live recognizer.

This is one recording, not independent exhaustive labels or a live navigation guarantee.

No qualified full receipt detector or stack quantity semantics; no autonomous purchase dispatch. `PurchaseProof` is an acceptance contract tested in isolation, not a live buy engine.
- Original repository main, Step13 branch, historical files and local installation are unchanged. Only the separate prototype checkout and per-engine archive/config directories are created. User must close another FM Rush instance before using this launcher; bridge binding conflicts are possible if left open.
